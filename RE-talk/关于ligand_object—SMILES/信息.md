# 从 LigandObject 联合身份切换到单一 SMILES 身份：事实与证据

## 文档目的

本文记录 2026-09-13 只读考察得到的事实、证据来源和已经达成的设计共识，为 Matcher 后续从联合身份

```text
(object_key, PreparedLigand 顶层 smiles)
```

切换为单一身份

```text
PreparedLigand 顶层 smiles
```

提供可复核依据。本文不是实现记录：截至本文写成时，没有修改 Matcher、AdaLigand、PocketXMol 的代码或配置，也没有改写服务器文件。

## 术语与身份边界

- PreparedLigand 顶层 smiles：AdaLigand `prepared_smiles.jsonl` 每条记录的顶层 `smiles`，即交给语言模型公开接口的 canonical non-isomeric SMILES。语言模型结果、向量 NPZ 和当前 Matcher 清单把它的逐字副本保存为 `prepared_smiles`。新身份的源字段始终是顶层 `smiles`；派生副本必须与源字符串逐字相等。本文后文把该源字符串及其已核验副本简称为“精确 SMILES”。
- model_smiles：语言模型 tokenizer 实际接收字符串的诊断字段。它可以为空，不能用于定义身份。
- occurrence：一个 PDB 内由 `candidate_id` 定位的具体配体实例。它的位置、沉积坐标和原子完整性属于实例属性，不属于化学身份。
- object_key：现行 LigandObject 模板键。它同时承担模板图定位和身份分组，后续正式管线不再把它作为 Matcher 身份或图读取入口。
- 单一 SMILES 身份：同一 PDB 内，PreparedLigand 顶层 smiles 完全相同的 occurrence 共享一个 Matcher 身份槽。不同 PDB 仍分别建立监督集合；不会因为字符串相同而跨 PDB 合并候选监督。

## 已经接受的科学决策

| 决策 | 结论 |
|---|---|
| 新 Matcher 的图真值 | 接受 PreparedLigand 顶层 smiles 经 RDKit 严格解析得到的重原子化学图，不要求与旧 LigandObject 图无损等价。 |
| 身份键 | 由 `(object_key, prepared_smiles)` 改为 `prepared_smiles`。 |
| 图特征 | 只保留 SMILES 能确定的原子序数、形式电荷、3/4/5/6 元环标志、化学键端点、键型和 3/4/5/6 元环标志。 |
| 删除的旧模板特征 | 删除参考坐标、参考构象键长、`residue_id`、模板 `is_present` 和七维模板手性。 |
| seen/unseen | 从清单、Dataset、Batch、训练和评估中完全删除，不建立替代统计。 |
| 历史模型 | 不兼容旧 checkpoint；新任务允许重写监督身份并从头训练。 |
| LigandObject 历史资产 | 保留现有代码和产物，允许在一次性坐标迁移中读取；未来正式 Matcher→PocketXMol 管线不读取它。 |
| 立体化学 | 顶层 smiles 是 non-isomeric，因此新身份有意不区分立体异构。当前 PocketXMol 模板手性均为 `CHI_UNSPECIFIED`，没有丢失其现行模型实际使用的手性信息。 |
| 异常 SMILES | 不引入宽容解析、备用模板或运行时特殊分支。无法通过统一严格门禁的 occurrence 整体排除。测试口径的一个边界见“严格解析失败项”。 |

## PocketXMol 四个划分的直接图等价证据

只读审计覆盖了 PocketXMol 当前冻结的 train、validation、calibration、test 四个划分。审计对每个正式 occurrence 执行：

```text
精确 prepared_smiles
→ RDKit 以原字符串解析
→ 保留字符串中显式氢完成初始解析
→ RemoveHs
→ 严格 sanitize
→ 与现行 PocketXMol LigandObject 重原子图做完整双向同构比较
```

审计比较了原子序数、形式电荷、化学键端点和键型；比较允许原子重编号，但不允许删改原子或化学键。

| 项目 | 结果 |
|---|---:|
| train occurrence | 65,290 |
| validation occurrence | 781 |
| calibration occurrence | 361 |
| test occurrence | 446 |
| 四划分 occurrence 合计 | 66,878 |
| 精确 prepared_smiles 数 | 1,979 |
| `(prepared_smiles, object_key)` 对数 | 2,039 |
| 与现行 Stage3 图双向同构 | 2,039 / 2,039 |
| 图不匹配、原子不匹配、化学键不匹配 | 0 |
| 严格解析失败 | 0 |
| 多片段分子 | 0 |
| 原字符串含显式氢 | 2,034 / 2,039 |

因此，在 PocketXMol 当前正式四划分的完整范围内，精确 PreparedLigand 顶层 smiles 可以无歧义地重建 PocketXMol 目前实际使用的重原子化学图。这个结论是 SMILES 重建图与 Stage3 当前图的直接比较，不依赖“同一 SMILES 下多个 object_key 彼此等价”的间接推断。

## 同一 SMILES 对应多个 object_key 的现状

PocketXMol 四划分共有 57 个跨数据集的多 object_key SMILES 家族，其中 6 组在同一 PDB 内出现：

| PDB | 现行 object_key |
|---|---|
| `6et5` | `NS0`、`NS5` |
| `6zxa` | `QS2`、`QSE` |
| `7nsg` | `UR5`、`UR8` |
| `8p73` | `X50`、`X58` |
| `9giy` | `A1IMZ`、`LO7` |
| `9j2f` | `NS0`、`NS5` |

这些组的精确 SMILES 重建图与各自 Stage3 当前图均同构；此前只读审计还确认同组 SMI-TED 向量逐位相同。它们证明 object_key 可以改变 Matcher 内部模板表示，却不改变 PocketXMol 所需的化学图。

## Matcher train/validation 的身份影响

当前 closed-set schema 4 清单中：

| 项目 | train | validation | 合计 |
|---|---:|---:|---:|
| 联合身份槽 | 1,477 | 536 | 2,013 |
| occurrence 成员数 | — | — | 14,750 |

两划分共有 435 个精确 prepared_smiles、451 个 `(prepared_smiles, object_key)` 对。改成同一 PDB 内按单一 SMILES 分组后：

| 划分 | 原身份槽 | 新身份槽 | 合并组数 | 涉及 occurrence |
|---|---:|---:|---:|---:|
| train | 1,477 | 1,475 | 2 | 16 |
| validation | 536 | 535 | 1 | 6 |

三个合并组是：

- train `8i8d`：`BRANCHED:OP3-PN7` 与 `BRANCHED:PN7-OP3`；
- train `8jx8`：`CCD:A2G` 与 `CCD:NAG`；
- validation `6rkd`：`BRANCHED:ATP-MOO` 与 `BRANCHED:MOO-ATP`。

所有可用的 MolFormer、SMI-TED 成员向量在合并组内逐位相等，最大绝对差为 0。`6rkd` 的 SMI-TED 向量不可用，但 MolFormer 向量逐位相等。train/validation 内没有同一 PDB、同一精确 SMILES 同时对应多个类别的情况。因此，身份槽合并本身对当前有效语言监督影响很小；图真值切换则是明确的新科学任务。

## 新旧 Matcher 图不是无损替换

对 451 个精确 `(prepared_smiles, object_key)` 对的只读图审计结果如下：

| 类别 | SMILES/object_key 对 | 身份记录 | occurrence 成员 |
|---|---:|---:|---:|
| 严格 SMILES 图与旧模板同构 | 371 | 1,637 | 11,789 |
| 严格 SMILES 图有效，但与旧模板不同 | 69 | 365 | 2,807 |
| 严格 SMILES 图有效，但旧模板自身不能严格 sanitize | 8 | 8 | 146 |
| 精确 prepared_smiles 不能严格 sanitize | 3 | 3 | 8 |

所以，新图不是 LigandObject 的换格式副本。它把语言模型真正收到的化学结构确立为新的监督图真值。该差异已由用户明确接受，后续必须从头训练，不能以 checkpoint 兼容作为设计目标。

## 严格解析失败项与测试边界

### 当前 train/validation

435 个精确 prepared_smiles 中，433 个可在 `RemoveHs` 后通过严格 sanitize。其余 2 个字符串形成 3 个现行身份槽、8 个 occurrence：

| 划分 | PDB | 现行 object_key | occurrence 数 | 语言向量状态 |
|---|---|---|---:|---|
| train | `9cr0` | `CCD:ICS` | 2 | SMI-TED 可用 |
| validation | `6rkd` | `BRANCHED:ATP-MOO...` | 5 | SMI-TED 不可用 |
| validation | `6rkd` | `BRANCHED:MOO-ATP...` | 1 | SMI-TED 不可用 |

这里的字符串能被 RDKit 以 `sanitize=False` 读成句法图，但不能通过严格化学检查。建议不保留句法图，不回退到 LigandObject，也不添加针对两个字符串的特殊代码；在新清单构建前统一排除这些 occurrence。

### held-out 测试清单

上述 `ICS` 和 `MOO` 两类字符串没有出现在 held-out `test_0` 或 `test_1`。但是，只读检查发现另一种严格解析失败字符串出现在 PDB `9oq7` 的 `candidate_id=4,10,13`：

- 三个 occurrence 同时列在 `test_0` 和 `test_1`；它们是同三条记录在两个测试清单中的重复引用，不是六个独立 occurrence；
- 三条语言准备记录当前均为 `status="model_failed"`；
- 它们不在 PocketXMol 当前 446 个正式 test occurrence 中，因为没有通过 Stage3 累计筛选。

因此，不能声称“所有严格解析失败项都不在测试集”。实现前需要明确采用以下简单的一致规则：任何划分中的 occurrence 只要精确 prepared_smiles 不能通过统一严格门禁，就不进入候选清单、身份清单、Dataset 长度和评估分母。该规则没有运行时例外，但会使未来 Matcher held-out 口径排除 `9oq7` 的三条记录；这项口径变化需要在开始改代码前得到明确确认。

## 自同构为什么不造成 Matcher 歧义

PocketXMol 当前正式模板的自同构数量分布为：

| 自同构数量 | 模板数 |
|---|---:|
| 1 | 615 |
| 2–10 | 1,240 |
| 11–100 | 162 |
| 101–1,000 | 19 |
| 1,001–10,000 | 3 |

同一分子存在多个自同构，表示在保持元素、电荷和全部化学键不变时，可以对等价原子重新编号；它不表示一个 SMILES 会产生多种化学图。

- Matcher 只给完整配体身份打分，没有逐原子坐标监督，因此不需要选择某一个自同构。图的基础原子顺序只需确定；实现验收仍应通过原子置换测试，证明图编码和最终身份分数在数值容差内不依赖节点编号。
- PocketXMol 预测并评估逐原子坐标，因此需要 `matches_iso` 做对称性重分配和 RMSD。该数组应由 Stage3 从同一 SMILES 图派生，不应塞进 Matcher 的公共图资产。
- 一次性坐标迁移只需把真值坐标排列到一个确定的 SMILES 基础顺序。若旧模板到 SMILES 图存在多个完整同构，可选择字典序最小的原子映射；其它映射只差一个自同构，Stage3 已有的对称性逻辑负责处理。

## 当前结论

方案在科学上可行，并且符合“身份只由语言模型公开接口输入决定、未来正式管线不读取 LigandObject、减少运行时代码分支”的目标。最稳妥的实现不是训练时反复解析 SMILES，而是离线生成按 `(pdb_id, exact prepared_smiles)` 查询的最小图归档；查询键仍是两个可读字段，不新增 `graph_id`，也不把 object_key 换名后重新引入。

当前唯一尚未获得明确授权的边界是：是否接受统一严格门禁从未来 Matcher held-out 测试口径中排除 `9oq7` 的 3 个 `model_failed` occurrence。除该口径确认外，Matcher 实施范围和 Stage3 交接范围已可具体定义。
