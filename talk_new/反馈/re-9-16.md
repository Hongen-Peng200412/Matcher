## 一、结论

这次重整可行，而且不需要从头重写 Matcher。正确做法是：

1. 把 `matcher/smiles_identity/` 中已经通过真实数据与 GPU 门禁的单一 SMILES 数据逻辑迁回历史分层目录；

### 2.4 Find_1 的当前输入与测试接口不同

Find_1 `F2_centered.npz` 提供 supplied 48 立方体、50 维 A L0、A/P 多尺度特征、64 维 V 特征、概率、坐标和裁剪信息。Matcher 现有 SMILES 管线在内存中构造 56 个密度通道和 50 个受体原子栅格通道，共 106 通道；不额外落盘 100 维以上的体素输入，PP 也从 `source_probability_48` 现场生成。

真实受体与 CryoAtom2 的 `test_0` 各有 179 个 PDB。测试集的 `F2_centered.npz` 不含 `score/selected`；冻结 Gaussian 分数、选择掩码和完整候选—occurrence 交集事实位于每个 PDB 的：

```text
evaluation/f2_centered_gaussian_macro_selected.npz
```

测试接入必须用 `(pdb_id, source_blob_index)` 连接 centered 数据和 evaluation NPZ，不能假定测试 centered 文件与 validation 有相同字段。两种受体条件的 179 个 PDB 均已核实为一一可连接。

evaluation NPZ 当前只预存 `topk_values=[3,4,5]`，但其中的 `candidate_score`、`candidate_selected`、`intersections`、`pred_sizes`、`gt_sizes` 和 `occurrence_id` 足以机械重算 `k=1,...,20`。

测试身份资产还需要区分两种现象。只读审计没有发现“精确 SMILES 可严格构图，但对应 SMI-TED 文件偶然缺失”的测试身份；因此不需要为测试集设计一种常规的语言文件缺失状态。已知不受支持的身份来自两个 PDB、五个 occurrence：

- `9ian` 的 `occurrence_id=0,5`；其中 occurrence 0 是唯一目标时，在 F2/Gaussian 排序中分别位于真实受体已选候选的第 3 名和 CryoAtom2 已选候选的第 5 名；
- `9oq7` 的 `occurrence_id=4,10,13`；其中 occurrence 10 是唯一目标时，在 F2/Gaussian 排序中分别位于真实受体已选候选的第 2 名和 CryoAtom2 已选候选的第 1 名。

五个 occurrence 都同时缺少合法 SMILES 图和 SMI-TED 语言资产：`9ian` 是 RDKit 无法解析的铁硫复杂结构字符串，`9oq7` 也是现有严格图构造不能接受的字符串。这不是文件漏产，而是精确字符串不属于图包和可预测身份轴。两个 PDB 同时属于 179-PDB `test_0` 和 149-PDB `test_1`，不能靠换用子集规避。

处理规则已经冻结为：保留这两个目标候选的原 Stage1 排名，前景二分类照常评价；真实前景候选上的 SMILES 匹配准确率把它们标记为“不具备受支持身份”并从分母排除；Stage1 top-k 曲线仍可由它们命中，Stage1+Matcher 曲线中它们不能形成命中，也绝不删除候选后让后一名补位。评估结果必须同时保存受影响的 PDB、候选编号和 `occurrence_id`，不能只保存一个总数。

## 三、冻结后的科学契约

### 3.1 身份与图

一个 Matcher 身份槽只由精确的顶层 `PreparedLigand.smiles` 定义。该字符串是 AdaLigand `prepared_smiles.jsonl` 中实际交给语言模型公开接口的 canonical non-isomeric SMILES。

以下内容不得重新进入身份定义或正式运行链：

- `object_key`；
- occurrence 坐标；
- `present` 掩码；
- 沉积原子选择；
- `model_smiles`；
- seen/unseen；
- MolFormer 或语言家族开关；
- graph ID；
- v3/v4 身份兼容分支。

全局图包继续保存：原子序数、形式电荷、原子环大小标志、化学键端点、键型和化学键环大小标志。坐标不进入图包。

### 3.2 每个候选只有一个确定监督目标

训练身份监督、validation SMILES 匹配准确率、test SMILES 匹配准确率和 PDB top-k 统一复用同一个目标选择规则：

1. 候选覆盖率和 occurrence 覆盖率都必须大于或等于 0.30；
2. 在全部合格 occurrence 中最大化两种覆盖率乘积的平方根；
3. 分数并列时选择较小的 `occurrence_id`；
4. 所选 occurrence 的精确顶层 `PreparedLigand.smiles` 是该候选唯一正确答案。

该规则不能在测试时改成“命中任一重叠 SMILES”。这样做很重要：`test_0` 的 Stage1 已选候选中，真实受体有 20 个、CryoAtom2 有 18 个同时覆盖多个不同 SMILES；如果测试另用多答案口径，会与训练监督不一致并虚增结果。

`type_tag=other` 或没有合格 occurrence 的候选是二分类负类。当前 `test_0` 的 occurrence 轴没有 `other`，但代码仍必须保留这一通用定义。

### 3.3 清单保存全部候选，Dataset 决定训练子集

正式 manifest 保存全部 centered 候选，不在构建时丢掉 `selected=False`。训练配置提供一个明确字段：

```yaml
data:
  selected_only: true
```

- `true` 是四项正式实验的默认值，只训练 Stage1 冻结选择后的候选；
- `false` 允许将来有意识地训练全部 centered 候选；
- 改变该字段会改变训练分布，不能在本轮偷偷形成第五个正式实验；
- 正式 validation 和 test 指标固定使用 `candidate_selected=True` 候选，使模型选择与部署候选范围一致。

对 train/validation，读取 manifest 时自然执行唯一过滤规则：确定前景目标不在当前 PDB 的“合法图且存在 SMI-TED 向量”身份轴中，就跳过整条训练/验证候选；背景候选保留。这里不引入 `available/missing_file/model_failed/not_applicable` 等运行时状态机，只在清单摘要报告跳过数和原因计数。对 test，合法图身份没有发现 SMI-TED 文件缺失；`9ian` 与 `9oq7` 的严格解析失败目标按上一节的显式测试边界处理，而不伪装成普通语言文件缺失。

### 3.4 前景过滤与 SMILES 匹配解耦

模型只保留一个前景二分类 logit：

```text
foreground_logit > 对应更可能是真实五类前景
```

五种配体类别只作为真实标签侧的分层信息，不再由模型预测，也不进入身份打分。

这项改造必须同时删除当前隐藏耦合：

- 删除六分类 `class_logits`；
- 删除 `identity_class_index` 模型输入；
- 删除 PairScorer 中“身份所属类别的六分类概率”；
- 删除 `oracle`、`detached`、`joint`、`identity_variant` 及全部历史兼容分支；
- SMILES 身份交叉熵对所有身份资产可用的真实前景候选直接计算；
- SMILES 匹配准确率不以二分类预测正确为条件；
- 模型即使把候选判成背景，也仍为它返回当前 PDB 闭集中的 argmax SMILES。

新版只保留一种身份损失：

```python
eligible = foreground_target & identity_supported
smiles_identity_ce = cross_entropy(
    identity_logits[eligible],
    identity_target[eligible],
)
```

`foreground_target=True` 表示候选按第 3.2 节的确定规则匹配到五类真实前景 occurrence；`identity_supported=True` 表示该唯一目标 SMILES 同时具有合法图和 SMI-TED 向量。直接交叉熵不乘前景概率，也不依赖二分类是否预测正确。前景头和身份头可以共享候选编码器，但活动 YAML、模型配置和运行时代码不提供身份损失变体或切回旧行为的开关。一次性迁移记录可以说明该计算方式沿用了历史最优身份损失，当前科学契约不再使用旧损失名称。

### 3.5 辅助损失的地位

最强、density-blob-only 和 trunk-only 可继续保留 ligand-area 与 binding-area 区域头及辅助损失，默认沿用历史权重 0.10。它们只帮助训练共享体素表示：

- 不作为正式 validation 科学指标；
- 不进入 selection；
- 不进入最终七栏图；
- W&B 只把它们记录为损失与运行诊断。

pocket-only 不执行 U-Net，因此不构造区域头，也不计算两项区域辅助损失。这个差异是该模态消融定义的一部分，不能用一个不参与候选表示的幽灵 U-Net 补齐。

### 3.6 validation 指标、BEST 与前景阈值

正式 validation 只保留两族科学指标。

第一族是前景过滤：

- 正类固定为真实五类前景；
- 在 `candidate_selected=True` 候选上汇总候选级 F1；
- 在同一集合上汇总 PRAUC；
- PRAUC 明确定义为按预测前景概率降序、同分组共同处理的 average precision，不使用图形插值造成第二种口径。

第二族是真实前景候选上的 SMILES 匹配准确率：

- 只统计 `candidate_selected=True`、确定目标为五类前景且目标图与语言向量可用的候选；
- 预测是同 PDB 身份 logits 的 argmax；
- 报告总体准确率；
- 另按真实类别报告 small molecule、sugar、metal/ion、peptide-like 和 nucleotide-like 准确率；
- 每项必须同时报告 `eligible_count`；测试时另报告候选级 `unsupported_identity_target_candidate_count`，并保存对应的 PDB、候选编号与 `occurrence_id`，但不把它设计成训练清单状态；分母为零时写 `N/A`，不能写成 0。

这里的“准确”是指：对一个按第 3.2 节规则确定为真实前景且身份受支持的候选，当前 PDB 身份 logits 的 argmax SMILES 与该候选唯一 `target_smiles` 逐字相同。它不是 PDB 候选排序中的 top-k，也不以二分类预测结果为条件。

BEST 与早停的唯一选择分数固定为：

$$
S_{\mathrm{selection}}
=
\frac{
\operatorname{PRAUC}_{\mathrm{foreground}}
+
\operatorname{Accuracy}_{\mathrm{SMILES}\mid\mathrm{true\ foreground,\ supported}}
}{2}.
$$

F1 不参与选模，因为它需要从同一 validation 拟合阈值。选定 BEST checkpoint 后，在 validation 的前景概率上只执行一次阈值搜索：最大化 F1；并列时取较高阈值，使前景接受更保守。BEST checkpoint 必须保存：

- `foreground_threshold`；
- 正类定义；
- 对应 validation F1 与 PRAUC；
- 真实前景候选上的总体 SMILES 匹配准确率；
- selection；
- manifest 身份与正式模型配置。

同一个 Matcher 前景阈值原样用于真实受体和 CryoAtom2 test，不在 CryoAtom2 上重新拟合。项目不再读取 Matcher calibration split，也不保留 `matcher/evaluation/calibration.py` 的活动入口。

### 3.7 当前任务是 PDB 内给定候选 SMILES 集合的闭集匹配

每个 PDB 的身份轴由该 PDB 真实 occurrence 的有效精确 SMILES 构建。模型解决“已给定该 PDB 的候选 SMILES 清单时，哪个 SMILES 与当前 blob 匹配”，不解决从任意化学空间发现未知配体。

正式报告必须明示这份候选 SMILES 清单的来源，不能把测试真值清单表述为无需外部候选库的端到端未知配体识别。未来若改用外部提供的候选库，应另立科学任务，不混入本轮四项实验。

## 五、只有两个公开动作的 manifest 设计

清单系统不再拆成“写标签旁路、构建候选、构建身份、再连接”的多段运行链。训练人员只需要理解并调用两个公开动作；内部可以保留短小的纯函数以避免巨型函数，但不得再暴露第二套构建入口、四态缺失系统或 Dataset 现场补建逻辑。确定目标的科学规则位于 `matcher/data/labels.py`，目录扫描、穷举审计和发布位于 `ops/matcher/`，运行时 manifest 读取保持简短。

### 5.1 扫描 Stage1 产物并建立清单

```python
build_stage1_manifest(stage1_root, split, output_path, *, data_root, graph_asset_path)
```

该函数是 `ops/matcher/` 中唯一正式 manifest 构建入口，对给定 `stage1_root` 执行一次确定性扫描：

1. 枚举已有 PDB 目录及 `F2_centered.npz`；
2. 读取同一 Stage1 产物根中的冻结 Gaussian 分数和 `selected` 掩码；
3. 用候选—occurrence 交集、两个 0.30 阈值、几何平均和较小 `occurrence_id` 规则确定唯一目标；
4. 连接顶层 `PreparedLigand.smiles`、全局图包成员和 SMI-TED 向量；
5. 审计完成标记、必需字段、候选轴、编号连接、资产成员和有限数值；
6. 把全部 centered 候选写入一个版本化 manifest 入口，并原子发布计数摘要。

几何监督直接写入 manifest 候选记录，不再生成活动的 `F2_centered_label.npz`。历史标签文件可以保留为既有取证，但训练和新清单不得依赖它。这样，清单不会因为旁路标签是否先生成而形成第二种状态。

候选记录只保存运行需要的字段：

- `pdb_id`；
- `centered_box_index`；
- `source_blob_index`；
- `candidate_selected`；
- `gaussian_score`；
- `source_probability_mean`；
- `foreground_target`；
- `target_category`；
- `matched_occurrence_id`；
- `target_smiles`；
- `candidate_coverage`、`occurrence_coverage` 和 `overlap_score`。

每个 PDB 的可预测身份记录只保存精确 `smiles` 和 SMI-TED 向量相对路径。manifest 元数据记录 schema 版本、精确来源根、图包路径、类别顺序、按字典序冻结的 PDB 集合与计数摘要；不保存 `object_key`、seen/unseen、语言家族、身份范围、图编号或重复的模型字符串。

训练与 validation 可以由同一个 manifest 入口记录两个 split；真实受体 `test_0` 与 CryoAtom2 `test_0` 分别建立同 schema 的 manifest，因为二者的 Stage1 产物根、Gaussian 分数和选择掩码不同。正式训练不要求扫描固定 50 个分片；用户指定的训练输入闭合后，构建入口冻结当次精确 PDB 集合，四项训练共同读取该版本，后续新增数据不得原地追加。

### 5.2 读取清单并建立训练 Dataset

```python
load_manifest_dataset(manifest_path, *, split, selected_only, mode)
```

该函数是训练、validation 和冻结测试读取清单的唯一入口：

- `selected_only` 只在读取阶段过滤候选；manifest 始终保存全部 centered 候选；
- `mode=train` 或 `validation` 时，前景目标不在可预测身份轴中就自然跳过整条候选，背景候选正常保留；
- `mode=test` 不做训练样本过滤，保留固定 PDB 与候选事实供 SMILES 匹配准确率和 top-k 评估；
- 图包由每个持久 DataLoader worker 完整载入一次，单样本读取不重新打开或解析图文件；
- 缺少 manifest、schema 不符、来源根不一致或数组形状错误时失败关闭，不在 Dataset 中现场重建清单。

因此，外部调用关系固定为：

```text
一个 Stage1 产物目录
    -> build_stage1_manifest(...)
    -> 一个 manifest 入口
    -> load_manifest_dataset(...)
    -> 训练、validation 或冻结测试
```

`selected_only=false` 只是同一读取函数的明确参数，不会生成第二份候选事实，也不在本轮形成第五项正式实验。

## 六、四个且仅四个正式实验

四项使用同一份冻结 train/validation manifest、同一随机种子、同一优化参数、同一身份资产、同一 validation 指标和同一测试脚本。除下表定义的结构变化外，不增加其它科学变量。

### 6.1 共同参数

沿用历史 top1 的已验证经验：

- SMI-TED 289M；
- 从零训练，不加载历史 checkpoint；
- seed 3409；
- AdamW，学习率 `1e-4`，weight decay `1e-4`；
- 名义 global batch 固定为 32；单卡 A800 首先尝试物理 batch 32、梯度累积 1；
- BF16；
- 梯度裁剪阈值 200；
- model dim 256，8 个注意力头，dropout 0.10；
- RAUNet planes `[64,256,256,256,256,256,128,64,64]`；
- recycle 3，bottleneck attention 4，图层 4；
- patience 2；
- `selected_only=true`；
- 前景 BCE 权重 1.0、直接 SMILES 身份交叉熵权重 1.0；
- 有区域主干的变体保留 ligand/binding 两项 0.10 辅助损失。

### 6.2 结构边界

| 变体 | 候选侧 | 身份侧 | 区域辅助损失 |
|---|---|---|---|
| `strongest` | 106 通道 U-Net；A 230、P 116、V 68、PP 4；mean/max 与候选条件注意力摘要拼接；12 项模态统计和 4 项采样统计 | native 语言、SMILES 图、同 PDB 其它身份三分支；图门和清单门从 0 开始学习 | 保留 |
| `density_blob_only` | U-Net 只读 supplied 实验密度经 `exp_clipnorm_nopost` 规则生成的 1 个通道；保留 V/blob token 及其同位置 U-Net 调制、V 的 count/mean/max 三项统计和 4 项采样统计；不读取模拟密度、受体 hardmask、额外 50 个受体原子栅格或 A/P/PP | 与 strongest 相同 | 保留 |
| `pocket_only` | 只读取 A token 的原始 50 维 L0；不读 A probability、坐标或 L1/L2/L3；不执行 U-Net；不用 V/P/PP；A 经投影后做掩码 mean/max | 与 strongest 相同 | 删除 |
| `trunk_only` | 与 strongest 完全相同 | 只保留语言向量投影和 native PairScorer；不构造图编码器、图注意力、身份清单注意力、两个增量打分器和门参数 | 保留 |

`density_blob_only` 不先构造历史 56 通道再切片。`matcher/data/density.py` 提供一个公开函数，直接把 supplied 实验密度按现有 0.1% 与 99.9% 分位截断并执行 z-score，返回 `(1,Z,Y,X)`。该变体仍保留 V/blob token、V 三项统计和四项裁剪统计，因此名称保持 `density_blob_only`，不将其表述成完全不含 blob 信息的纯密度模型。

单卡 A800 若物理 batch 32 发生 OOM，则使用同一随机种子从头重启，并依次尝试 `16 × 2`、`8 × 4` 等保持名义 global batch 32 的组合。失败进程不得从已经执行过部分优化步骤的状态继续；任务记录保存实际物理 batch 与梯度累积。该资源回退不改变科学变量，也不需要再次审批。

四个 YAML 只允许 `model.variant` 取上述四个值，不保留可以任意拼出第五、第六种模型的开关矩阵。`selected_only=false` 和两种 top-k 排序只是接口能力，不在本轮新增训练任务。

## 七、正式测试与图表

### 7.1 候选排序

测试脚本在同一次冻结 Matcher 前向后必须同时计算两种正式排序，不提供只运行其中一种的科学配置开关：

1. Gaussian 排序使用冻结 `candidate_score`。
2. blob 概率均值排序使用同一候选的 `source_probability_mean`。

两种排序都只在 `candidate_selected=True` 子序列中进行；分数并列时沿用 Stage1 的稳定候选顺序，以较小 `source_blob_index` 优先。使用 blob 概率均值时，选择掩码仍是已冻结的 F2/Gaussian `candidate_selected`，只改变集合内部顺序，不暗中更换候选集合。两种排序共享同一份 Matcher 预测，不重新训练，也不形成第五个模型实验。

### 7.2 PDB top-k 定义

对每个 PDB 和每个 `k=1,...,20`：

1. 取 Stage1 `candidate_selected=True` 候选，按所选排序分数降序排列；
2. 候选少于 k 时使用全部已有候选，曲线随后自然平台；
3. Stage1-only hit：前 k 个候选中至少一个确定性目标为真实五类前景；
4. Stage1+Matcher hit：前 k 个候选中至少一个确定性目标为真实五类前景，且 Matcher argmax SMILES 与该候选唯一 `target_smiles` 逐字相同；
5. Matcher 前景阈值不参与四条 top-k 曲线，因为用户要求即使是假阳性候选也返回一个 SMILES；
6. 分母固定为 `test_0` 的 179 个 PDB，不因目标资产缺失而删除 PDB。

`9ian` 与 `9oq7` 合计在每种受体条件下形成两个不受支持目标候选，它们仍占据各自原始排名。它们可以让 Stage1-only 曲线命中，但不能让 Stage1+Matcher 曲线命中；评估器不得先删除它们再把后续候选向前补位。

F2/Gaussian、覆盖阈值 0.30 的 Stage1-only 机械门禁基线为：

- 真实受体 top-1/2/3/4 命中数：`136/153/159/164`，分母 179；
- CryoAtom2 top-1/2/3/4 命中数：`118/132/145/147`，最终平台分别为 164 和 151。

新 evaluator 必须先复现这些既有 Stage1-only 事实，再加入 Matcher 条件。

### 7.3 三张正式图

第一张图使用 paired bars 比较真实受体与 CryoAtom2。主面板严格保留七组：

1. 真实前景候选上的总体 SMILES 匹配准确率；
2. small molecule SMILES 匹配准确率；
3. sugar SMILES 匹配准确率；
4. metal/ion SMILES 匹配准确率；
5. peptide-like SMILES 匹配准确率；
6. nucleotide-like SMILES 匹配准确率；
7. foreground F1。

PRAUC 不与 SMILES 匹配准确率或 F1 平均成一个虚构指标；它在同一张图的右侧窄面板或菱形标记中单独显示，并在结果表给出精确值。每个 SMILES 匹配准确率栏目必须标支持数。

现有 `test_0` 没有 nucleotide-like 确定目标，肽样目标在每种受体条件下只有 1 个。因此核酸状栏必须显示 `N/A (n=0)`，肽样栏必须显示 `n=1`，不能把零分母画成 0 分。

第二张图使用 Gaussian `candidate_score` 排序，横轴为 `k=1,...,20`，四条线为：

- 真实受体 Stage1-only；
- 真实受体 Stage1+Matcher；
- CryoAtom2 Stage1-only；
- CryoAtom2 Stage1+Matcher。

第三张图使用 `source_probability_mean` 排序，横轴和四条曲线与第二张图相同。两张 top-k 图具有同等正式地位，文件名和标题必须明确各自排序字段，不能相互覆盖。

正式测试入口只生成绘制三张图所需的冻结候选预测、支持数、逐 PDB 命中事实和两种排序的 `k=1,...,20` 汇总数组。`matcher/evaluation/plotting.py` 中的朴素绘图函数随后读取这些产物；测试入口不导入绘图模块，绘图函数也不加载模型或重新执行推理。

### 7.4 test_0、test_1 与两种受体条件的解释

`test_0` 是 179-PDB 主测试。`test_1` 是从同一 `test_0` 事实按 occurrence 数范围保序筛出的 149-PDB 子集；服务器没有一套独立的 test_1 模型前向。Matcher 必须复用 test_0 forward 后按官方 PDB 列表筛选，不能把 test_1 解释为独立复现或用于选模。

真实受体与 CryoAtom2 的 Stage1 F2/Gaussian 选择参数分别在各自 Stage1 校准流程中冻结，阈值、最小体素数和 Gaussian 参数并不相同。因此两种受体结果是“两套冻结完整流水线”的比较，不是只替换受体、其余逐字段相同的纯因果实验。Matcher 模型和 Matcher 前景阈值则必须完全相同。
