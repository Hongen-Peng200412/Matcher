## 一、结论

这项测试可行，而且不需要重建 Stage1 产物、重训 Matcher 或修改 PocketXMol。新增一份与现有 179-PDB `test_0` 并存的 `test_smallmolecule` 评测清单，并复用既有候选、唯一 occurrence 配对、冻结 Matcher checkpoint 和训练代码快照。

`test_smallmolecule` 的核心不是简单删除非 Stage3 候选，而是对每个 PDB 的冻结候选顺序应用一种新的尝试次数规则：

1. 真值为背景的候选消耗一次尝试；
2. 唯一配对 occurrence 不属于 Stage3 测试集的前景候选被跳过，不消耗尝试，也不运行 Matcher；
3. 唯一配对 occurrence 属于 Stage3 测试集的候选消耗一次尝试；Stage1-only 到此即算命中，Stage1＋Stage2 还要求 Matcher 的身份 logits 预测出该 occurrence 的精确 `PreparedLigand.smiles`；
4. 候选耗尽仍未命中时，该 PDB 在当前 k 下失败。

Stage1-only 与 Emap2lig 比较；Stage1＋Stage2 不与 Emap2lig 比较。两类测试均分别报告真实受体和 CryoAtom2 受体。Find_1 继续同时报告 Gaussian 分数和 blob 内概率均值两种排序；Emap2lig 只使用其实例内原生 ligand probability 均值排序。

Matcher 的最终答案范围按用户最新要求分成两档：

- **全配体答案范围**：在当前 PDB 的全部受支持精确 SMILES logits 上取 argmax，包括 small molecule、糖、金属/离子、肽样和核苷酸样身份；
- **small-molecule 答案范围**：复用同一次全身份 forward 的 logits，把原始 occurrence 标签不是 `small_molecule` 的身份槽屏蔽后再取 argmax。允许成为答案的集合不是 Stage3 真值集合；没有通过 Stage3 含碳、沉积完整性等累计条件的受支持 small-molecule SMILES 仍保留为干扰项。

两档始终向 Matcher forward 提供相同的完整 PDB 内身份轴，因此语言、图和同 PDB 身份清单注意力上下文完全相同。两档只改变最终允许成为答案的 logits 集合，不形成第二次模型前向，也不把它表述为 small-molecule-only 输入模型。

## 二、术语与测试边界

### 2.1 Stage3 测试 occurrence

本文中的 Stage3 测试 occurrence 是 PocketXMol 当前生产清单中的一条记录：

```text
(pdb_id, candidate_id)
```

其中 `candidate_id` 与 AdaLigand/Matcher 的 `occurrence_id` 是同一个 PDB 内编号。`prepared_smiles` 定义化学身份，`pdb_id＋candidate_id` 定位沉积实例和坐标。

Stage3 的累计筛选条件包括：继承原划分质量成员、`type_tag=small_molecule`、单残基单 CCD、非共价、含碳、元素与键受支持、严格 SMILES 图和语言资产有效、沉积重原子完整且坐标有限，以及必要受体和密度资产有效。本文不重新实现或重新解释这些条件，直接把 PocketXMol 已冻结的生产 `test.jsonl` 当作唯一成员来源。

### 2.2 候选唯一目标

Find_1、Emap2lig、Stage1-only 和 Stage1＋Stage2 共用 Matcher 已冻结的唯一目标规则：

1. 候选覆盖率和 occurrence 覆盖率均不低于 0.30；
2. 在合格 occurrence 中最大化两种覆盖率的几何平均；
3. 并列时选择较小的 `occurrence_id`；
4. 所选 occurrence 是该 blob 的唯一目标，其精确顶层 `PreparedLigand.smiles` 是唯一正确身份。

不得为了让候选进入 Stage3 测试而在全部有效覆盖 occurrence 中重新挑一个 Stage3 成员。用户已经确认真实受体 `9rd8/source_blob_index=0` 的边界：该候选同时有效覆盖 occurrence 0 和 occurrence 1，既有唯一规则选择不属于 Stage3 的 occurrence 0，因此它必须作为“非 Stage3 前景”跳过，不消耗尝试，也不运行 Matcher；不得临时改判为属于 Stage3 的 occurrence 1。

### 2.3 这不是盲目部署指标

“非 Stage3 前景不消耗尝试”的判断依赖真实 occurrence 配对和 Stage3 成员清单，因此它是一项**带真值适用范围门禁的评测**。它回答的是：在只对 Stage3 可对接小分子计费的条件下，Stage1 和 Matcher 能否找到并识别这些实例。

它不能被表述为无需真值的完全自主部署流程。本文会同时生成可供后续 PocketXMol 接线检查的中心和预测 SMILES，但该派生产物应标明 `evaluation_oracle_filtered`；真正的盲目端到端部署若也要免费跳过非 Stage3 occurrence，需要另行提供不依赖真值的运行时判别规则。

## 四、冻结测试契约

### 4.1 PDB 轴、候选轴与排名

每种来源在每个 PDB 内先建立唯一冻结候选顺序：

1. `candidate_selected=True` 候选排在前段；
2. `candidate_selected=False` 候选排在后段；
3. Find_1 Gaussian 排序在两段内分别按 `candidate_score` 降序；
4. Find_1 概率均值排序在两段内分别按 `source_probability_mean` 降序；
5. Emap2lig 只按实例内原生 ligand probability 均值降序；
6. 分数并列时保持现有稳定顺序，再以较小 `source_blob_index` 决胜；
7. unselected 候选只能追加在 selected 段之后，不能挤占 selected 的位置。

`test_smallmolecule` 不重跑 Stage1，不重建 Gaussian 分数，不改变候选选择掩码。真实受体、CryoAtom2 和 Emap2lig 保留各自候选集合；禁止按 blob 编号或空间位置把 Find 与 Emap2lig 候选一一配对。

### 4.2 尝试次数状态机

对每个 PDB、每种排序和每个 `k=1,...,20`，从冻结顺序开头扫描候选。设 `spent` 为已经消耗的尝试次数：

```text
spent = 0
for candidate in frozen_order:
    if candidate.unique_target is non_stage3_foreground:
        continue

    spent += 1

    if candidate.unique_target is background:
        if spent == k:
            fail
        continue

    # 到这里，唯一目标是 Stage3 test occurrence。
    if task is stage1_only:
        hit

    if task is stage1_plus_stage2:
        if predicted_smiles == target_smiles:
            hit
        if spent == k:
            fail
```

如果候选列表在 `spent` 达到 k 之前耗尽，也记为失败。结果必须同时保存：

- `raw_rank`：候选在完整冻结顺序中的一基位置；
- `attempt_index`：跳过非 Stage3 前景后的尝试编号，跳过项为 null；
- `action`：`skip_non_stage3_foreground`、`spend_background` 或 `spend_stage3_target`；
- 当前 k 是否已经命中。

保存这两种编号可以避免把“原始 top-k”与“跳过后的 k 次有效尝试”混为一谈。

### 4.3 Stage1-only

Stage1-only 不读取 Matcher checkpoint，也不使用 Matcher 前景阈值。唯一目标属于 Stage3 测试集时，该候选就是成功候选；背景消耗机会，非 Stage3 前景免费跳过。

正式报告内容为：

- Find_1 真实受体：Gaussian 与概率均值两条曲线；
- Find_1 CryoAtom2：Gaussian 与概率均值两条曲线；
- Emap2lig：一条 receptor-independent 的原生概率均值曲线；
- 每条曲线的 `hit_count`、`hit_rate=hit_count/77` 和逐 PDB 首次命中轨迹；
- 446 个 Stage3 occurrence 中具有任一有效候选覆盖的数量，作为 occurrence 级补充覆盖指标。

建议生成两张 Stage1-only 图：

1. Find_1 Gaussian 的真实受体、CryoAtom2 与 Emap2lig 原生均值基线；
2. Find_1 概率均值的真实受体、CryoAtom2 与同一条 Emap2lig 基线。

两张图中的 Emap2lig 曲线必须来自同一份数组并逐点相同，不能复制成真实受体和 CryoAtom2 两条线。

### 4.4 Stage1＋Stage2

Stage1＋Stage2 只对唯一目标属于 Stage3 的候选执行 Matcher 身份判断。逻辑上：

- 背景候选消耗一次尝试，但不需要运行 Matcher；
- 非 Stage3 前景候选免费跳过，也不运行 Matcher；
- Stage3 目标候选消耗一次尝试，并检查冻结 BEST 的身份预测；
- 预测 SMILES 错误时，本次尝试失败并继续下一候选；
- 预测 SMILES 与唯一目标的精确顶层 `PreparedLigand.smiles` 逐字相同时命中。

前景头和 validation 冻结前景阈值均不参与本项评测。原因是进入 Matcher 的候选已经由真值适用范围门禁确定为 Stage3 目标候选，本测试只考察给定该候选后的 SMILES 身份匹配。Stage2 不改变 Stage1 排名，也不使用 Matcher 的任何输出重排候选。

每个 Matcher 模型从同一次完整身份 forward 报告以下两个答案范围：

1. **全配体答案范围**：在原 `test_0` 完整身份轴的全部有效 logits 上取 argmax；
2. **small-molecule 答案范围**：在同一份 logits 上把 `type_tag != small_molecule` 的身份槽设为不可选，再在剩余 127 个受支持身份中取 argmax。

两档共用同一候选输入、完整身份轴、checkpoint、训练代码快照、Stage1 顺序和同一份原始 `identity_logits`；唯一变化是最终 argmax 前是否屏蔽非 small-molecule logits。结果必须保存完整身份轴、原始 logits、两种 argmax SMILES 和 small-molecule 答案掩码。

strongest 是主结果；density_blob_only 是既有消融的补充结果。两者使用各自冻结 BEST 和各自训练 release，不根据 `test_smallmolecule` 成绩重新选模型。Stage1＋Stage2 不绘制或报告 Emap2lig 联合曲线。

### 4.5 PDB 内同 SMILES 多 occurrence

Stage1 仍输出唯一 `matched_occurrence_id`，因此空间目标明确。Matcher 的正确性只比较精确 SMILES：若多个 Stage3 occurrence 共享同一 SMILES，Matcher 不需要也不能靠化学身份区分它们。后续 docking 的空间位置来自当前 blob 中心，不从 SMILES 推断 occurrence。

正式结果中应同时保留：

- 评测真值 `matched_occurrence_id`，用于核查 Stage1 配对；
- `target_smiles` 与 `predicted_smiles`，用于核查 Stage2；
- blob 世界坐标中心，供后续构造 PocketXMol 口袋；
- 不得把多个同 SMILES occurrence 合并成一个空间命中记录。

### 5.4 blob 中心的唯一定义

Find_1 应从完整 `F2_blobs.npz` 的 `voxel_index_global_zyx` 计算中心，不能直接使用 centered 框内的 `v_centroid_local_zyx`。原因是 77 个 PDB 中真实受体和 CryoAtom2 各有 1 个来源 blob 不能被 centered 框完整容纳；框内质心会因截断偏移。

设：

- `box_origin_world` 为 centered 80³ BOX 零索引网格角点的世界 XYZ；
- `box_start_zyx` 为该 BOX 在完整图中的 ZYX 起点；
- `voxel_size_world` 为世界 XYZ 体素尺寸；
- `full_blob_zyx` 为完整来源 blob 的全部全图 ZYX 整数索引。

则：

```text
grid_origin_xyz = box_origin_world
                  - reverse(box_start_zyx) * voxel_size_world

blob_center_world_xyz_A = grid_origin_xyz
                          + (reverse(mean(full_blob_zyx)) + 0.5)
                            * voxel_size_world
```

`+0.5` 表示取体素中心；均值不按概率加权。这与 Pocket_Plus 对 blob 体素质心的现有含义一致，也不会因为 centered 裁剪而改变。

Emap2lig 的 `mapped/{pdb_id}/official_blobs.npz` 已保存完整 `voxel_index_global_zyx`、`origin_xyz` 和 `voxel_size_xyz`，可以用同一“完整体素中心算术平均”定义保存其候选中心。Emap2lig 中心只用于结果审计和将来比较，不在本轮接入 Matcher 或 PocketXMol。

### 6.2 评估入口

评估职责按科学步骤拆分，但仍属于同一个独立工具：

### 6.3 一次身份前向与两种最终决策

评估 Dataset 仍从既有 `test_0` 完整身份记录读取图与 SMI-TED 表征：

- 每个候选只用当前 PDB 的全部 identity 记录建立一次 batch、图和完整 forward；
- 全配体预测直接对全部有效 `identity_logits` 取 argmax；
- small-molecule 预测先用 `identities.jsonl.allowed_as_small_molecule_answer` 把非 small-molecule 槽屏蔽，再取 argmax；
- 当前 Stage3 目标 SMILES 必须在完整身份轴中且允许成为 small-molecule 答案，否则失败关闭；
- 不能改变身份字典序、语言向量、图资产、候选张量或原始 logits；
- 不读取或使用前景头与冻结前景阈值；
- 不新增 checkpoint，不训练模型，不根据 `test_smallmolecule` 选择变体。

small-molecule 档的屏蔽应只作用于结果选择，不回写或覆盖保存的原始 logits。若一个 PDB 没有任何允许答案，评估应失败关闭；当前 77 个 PDB 均至少有 1 个受支持 small-molecule 身份。

模型加载沿用训练快照原则：从训练 run 的 source release 读取模型定义，而不是用以后可能已经覆盖的当前工作区实现。正式结果保存训练 source release、评估 release、launch、checkpoint 及其 SHA-256、训练 YAML、训练 manifest、评估 manifest、GPU 和数值后端。

## 八、机械门禁与科学验收

### 8.1 manifest 门禁

必须同时满足：

- Stage3 来源 SHA-256 与记录数匹配；
- 446 个 `(pdb_id, candidate_id)` 唯一，PDB 恰为 77 个；
- 77 个 PDB 都属于两份 179-PDB Matcher manifest；
- 真实受体候选 598，CryoAtom2 候选 632，Emap2lig 候选 30,561；

- 104 个 Stage3 `(pdb_id, prepared_smiles)` 全部存在于完整身份轴，且 small-molecule 答案掩码均为允许；
- 全配体身份 180、small-molecule 身份 127，混合类别身份 0，每个 PDB 的 small-molecule 身份数至少为 1；
- 每个候选通过 `(pdb_id, source_blob_index)` 唯一连接 centered、完整 blob 和原 manifest；
- 世界中心为有限长度 3 数组，单位与轴顺序固定为 Å、XYZ；
- 真实受体和 CryoAtom2 各 1 个 `source_blob_fits_centered_box=False` 的候选仍使用完整 blob 中心。

### 8.2 排名与尝试语义门禁

- selected 段相对旧 `test_0` 排名严格不变；
- unselected 只能追加；
- Find 的 Gaussian 与概率均值只改变段内分数键；

- 候选耗尽的 PDB 保留在 77 的固定分母；
- Stage1-only 正式实现应复现第 3.5 节只读预演的全部 20 个 k 点，而不只复现表中五个点。

### 8.3 Matcher 门禁

- checkpoint 从各自训练 source release 加载，不能用以后覆盖的工作区模型类；

- exact SMILES 比较逐字进行，不重新 canonicalize；
- 不读取 calibration，不在测试集拟合阈值，不用 `test_smallmolecule` 选择 checkpoint；
- 同一模型两种受体条件均使用该模型同一个 BEST。

### 8.4 结果门禁

- 所有曲线分母固定为 77，并保存逐 PDB 布尔值，汇总可机械重算；
- Stage1-only 与 Stage1＋Stage2 使用同一候选顺序和同一三态目标范围；

## 十一、当前讨论结论
