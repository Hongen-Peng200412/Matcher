# Matcher 单一 SMILES 主线重整需求

## 文档职责与当前状态

本文记录 Matcher 重整必须满足的用户需求和已经确认的科学边界。详细代码布局、训练参数、测试门禁与实施顺序见 [`re-9-16.md`](re-9-16.md)。

当前只批准修改讨论与规划文档，尚未批准正式修改代码、服务器文件、运行任务或 Git 历史。

## 一、重整目标

Matcher 当前同时保留历史正式管线和 `matcher/smiles_identity/` 平行管线，形成了两套 manifest、两套 Dataset、两套模型与训练入口。重整后的仓库必须只保留一条正式主线：

1. 以 `9e6e974dd98cba236290fcf59966ff2fb85cd49e` 作为历史比较基点，但不把代码回退到该提交。
2. 保留历史训练、BEST、早停、checkpoint、W&B、RAUNet、注意力和摘要拼接等已经验证的能力。
3. 采用已经验收的精确顶层 `PreparedLigand.smiles` 身份、SMILES 图包和 Find_1 数据适配。
4. 删除已经退出科学契约的 `object_key` 身份依赖、seen/unseen、六分类预测、calibration、重复 manifest 和历史兼容分支。
5. 将仍然有效的实现迁入 `matcher/data`、`matcher/datasets`、`matcher/model`、`matcher/training` 和 `matcher/evaluation`；迁移完成后删除整个 `matcher/smiles_identity/`。
6. 不保留没有新契约调用者的历史函数、代码块、配置或启动脚本。历史事实由 Git 与结果文档保存，不在活动代码中建立备份实现。

最终只能存在一个 manifest 入口、一个 CandidateDataset、一个 Batch 契约、一个 Matcher 模型入口、一个训练引擎和一个正式评估入口。

## 二、数据与监督契约

### 2.1 单一 SMILES 身份

一个身份槽只由精确的顶层 `PreparedLigand.smiles` 定义。身份不再包含 `object_key`、occurrence 坐标、`present` 掩码、沉积原子选择、`model_smiles`、seen/unseen 或新造的图编号。

每个候选只有一个确定目标：

1. 候选覆盖率和 occurrence 覆盖率都必须大于或等于 0.30。
2. 在合格 occurrence 中最大化两种覆盖率乘积的平方根。
3. 分数并列时选择较小的 `occurrence_id`。
4. 所选 occurrence 的精确顶层 SMILES 是唯一正确答案。

### 2.2 manifest 与 Dataset

manifest 保存全部 centered 候选及其 `candidate_selected`，不为 selected 与全部候选各建一份清单。正式训练、validation 和 test 默认只读取 `candidate_selected=True`；同一个 Dataset 入口允许显式读取全部候选，但该设置不构成本轮第五项实验。

训练人员只需要理解两个公开动作：

1. 扫描一个 Find_1 产物根并建立冻结 manifest。
2. 读取一个 manifest 并建立训练、validation 或 test Dataset。

确定目标的纯科学规则保留在正式 `matcher/data` 代码中。目录扫描、字段穷举检查、计数审计和原子发布位于 `ops/matcher/`，避免正式读取代码被大量一次性 `if` 与 `raise` 淹没。Dataset 不得现场重建清单或标签。

对 train/validation，真实前景候选的目标 SMILES 缺少合法图或 SMI-TED 向量时，整条候选自然跳过；背景候选保留。test 候选不得删除，以维持 Stage1 排名和二分类分母。

### 2.3 训练数据冻结

正式训练不要求等待预先设想的 50 个 train 分片全部完成。当用户通知可以开始训练时，参与本轮训练的全部输入必须已经闭合，并冻结精确、有序的 PDB 集合和 manifest。四个模型必须共享同一份 train/validation manifest；新完成的分片或新增数据不得在四项训练进行期间追加到其中某一项。

## 三、模型与损失

### 3.1 两个相互独立的任务

Matcher 只回答两个问题：

1. 当前候选是否为真实前景。模型输出一个前景 logit，以二元交叉熵训练，以 F1 和 PRAUC 评价。
2. 对真实前景候选，在当前 PDB 给定的候选 SMILES 集合中选择唯一正确的 SMILES。

模型删除六分类 `class_logits`、模型侧 `identity_class_index`、`identity_class_probability` 及 PairScorer 中对应的一维类别概率输入。五种配体类别只作为真值侧的结果分层，不参与模型前向。

### 3.2 直接 SMILES 身份交叉熵

新版只保留一种身份损失：

```python
eligible = foreground_target & identity_supported
smiles_identity_ce = cross_entropy(
    identity_logits[eligible],
    identity_target[eligible],
)
```

其中，`foreground_target=True` 表示候选按确定性覆盖规则匹配到五类真实前景 occurrence；`identity_supported=True` 表示目标 SMILES 同时具有合法图和 SMI-TED 向量。

活动 YAML、模型配置和运行时代码中不出现 `oracle`、`detached`、`joint` 或 `identity_variant`。直接身份交叉熵不乘前景概率，也不依赖二分类是否预测正确。迁移记录可以说明该计算方式沿用了历史最优身份损失，但活动代码不保存旧名称或兼容开关。

任务本身称为“PDB 内给定候选 SMILES 集合的闭集匹配任务”，不再使用容易与历史损失名称混淆的 `oracle closed-set`。

## 四、四个正式模型

本轮只训练以下四个具名变体：

1. `strongest`：沿用历史第一名的完整候选侧、mean/max 与候选条件注意力摘要拼接，以及语言、SMILES 图和同 PDB 其他 SMILES 摘要三条身份分支。
2. `density_blob_only`：U-Net 只读取 supplied 实验密度经 `exp_clipnorm_nopost` 规则处理得到的一个通道；保留 V/blob token、同位置 U-Net 调制、V 的 count/mean/max 三项统计和四项裁剪统计；删除 A、P、PP 和额外 50 个受体原子栅格通道。
3. `pocket_only`：只读取 A token 的原始 50 维 L0；不使用 A 概率、坐标、多尺度特征、U-Net、V、P 或 PP。
4. `trunk_only`：候选侧与 `strongest` 相同；身份侧只保留 SMI-TED 向量投影和主干 PairScorer，不构造 SMILES 图分支、同 PDB 其他 SMILES 摘要分支或相应门参数。

`strongest`、`density_blob_only` 和 `trunk_only` 保留 ligand-area 与 binding-area 两个区域辅助头及各 0.10 损失。两项区域损失只辅助共享体素表示，不进入正式 validation 指标、BEST 选择分数或最终图表。`pocket_only` 不实例化 U-Net 和区域头。

## 五、validation 与正式测试

### 5.1 validation 指标与 BEST

validation 只保留两族科学指标：

1. 前景过滤：在 `candidate_selected=True` 候选上报告 F1 与 PRAUC。
2. 真实前景候选上的 SMILES 匹配准确率：在目标身份资产可用的真实前景候选上，比较当前 PDB 身份 logits 的 argmax SMILES 与唯一目标 SMILES；总体和五种真实类别分别报告准确率与支持数。

SMILES 匹配准确率不要求二分类预测正确，也不使用前景阈值。模型即使把候选预测成背景，也仍然返回当前 PDB 身份轴上的 argmax SMILES。

BEST 与早停只使用：

$$
S_{\mathrm{selection}}
=
\frac{
\operatorname{PRAUC}_{\mathrm{foreground}}
+
\operatorname{Accuracy}_{\mathrm{SMILES}\mid\mathrm{true\ foreground,\ supported}}
}{2}.
$$

F1 阈值只在 BEST checkpoint 确定后用 validation 拟合，并随 checkpoint 保存；同一个阈值原样用于真实受体和 CryoAtom2 test。Matcher 不再使用 calibration split。

### 5.2 两种正式 top-k 排序

正式测试在同一次冻结 Matcher 前向后，同时报告两种候选排序：

1. 冻结 Gaussian `candidate_score`。
2. blob 内来源概率均值 `source_probability_mean`。

两种排序使用同一个 `candidate_selected=True` 候选集合，只改变集合内部顺序，并计算 `k=1,...,20`。排序变化不重新训练 Matcher，也不形成额外模型实验。

### 5.3 三张正式图

正式结果至少生成三张图：

1. 真实受体与 CryoAtom2 的前景指标、总体及五种类别的 SMILES 匹配准确率和支持数。
2. Gaussian 排序下，真实受体与 CryoAtom2 的 Stage1-only 和 Stage1+Matcher 四条 top-k 曲线。
3. `source_probability_mean` 排序下，同样四条 top-k 曲线。

测试入口只负责写出生成三张图所需的冻结候选预测、支持数和 `k=1,...,20` 命中数组。一个独立的朴素绘图函数只读取这些评估产物，不导入模型或重新执行推理。

`9ian` 和 `9oq7` 的不受支持目标候选保留原 Stage1 名次和前景二分类评价，但不进入 SMILES 匹配准确率分母，也不能让 Stage1+Matcher top-k 曲线命中。评估器不得删除这些候选后让后一名补位。

## 六、工程与文档要求

- manifest、训练和评估产物必须写入正式目录，不写入 `/storage/penghongen/tmp/Matcher/`。
- A800 单卡首先尝试物理 batch 32、梯度累积 1。发生 OOM 时依次减小物理 batch 并增加梯度累积，保持名义 global batch 32，使用同一随机种子从头重试，不需要额外科学审批。
- 迁移完成后删除没有新契约调用者的历史实现，不建立 archive 代码目录或兼容开关。
- `matcher/data`、`matcher/datasets`、`matcher/model`、`matcher/training`、`matcher/evaluation` 和正式脚本目录必须具有可冷读 README，说明代码组织脉络、推荐阅读顺序、稳定入口和主要科学契约。
- manifest、CandidateItem、CandidateBatch、评估结果等稳定科学产物还必须有字段级 README，说明数据类型、形状、特殊值、掩码与索引含义、跨文件对齐方式和具体示例。
- 测试命令和正式运行命令必须分开记录；正式入口保持短小、自包含。
- 后续代码与学习分支中的注释、Docstring、YAML 和 README 继续分别遵守项目既有中文技术表达规范。

只有在用户明确批准详细计划后，才可以修改代码、服务器文件、任务、锁或 Git 历史。
