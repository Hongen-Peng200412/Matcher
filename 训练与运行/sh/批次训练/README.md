# 固定批次训练入口

本目录把第 1–5 批的 21 份固定实验计划映射为零参数 Shell 入口。每个入口只完成四件事：拒绝额外参数、核验 `TASK_PROJECT_ROOT`、选择唯一 YAML、把执行权交给当前的 [`train_experiment.sh`](../train_experiment.sh)。

这些脚本按当前代码和依赖解释历史 YAML，不承诺复现最初实验环境。如果当前配置格式或依赖已经不兼容，脚本只能作为阅读历史计划与提交方式的入口。脚本也不管理资源占用、运行留证、远端查询或结果判定；这些职责仍由项目现有提交工具和训练入口承担。

## 使用契约

1. 从对应批次 README 选择固定脚本，并先核对脚本与 YAML 的一一映射。
2. 复制脚本头部给出的 [`submit_task.sh`](../../submit_task.sh) 命令；不要向固定脚本追加参数。
3. 提交工具设置 `TASK_PROJECT_ROOT` 后，脚本进入该目录并检查固定 YAML 与训练入口是否存在。
4. [`matcher.training.config.load_experiment_plan`](../../../matcher/training/config.py) 解析 YAML；训练入口执行其中唯一的训练阶段。

每个批次 README 同时列出资源标签、物理批量、梯度累积次数和全局批量。这里的“物理批量”指一次前向与反向计算实际接收的样本数；全局批量等于物理批量乘梯度累积次数。

## 阅读顺序

先读本文件确认边界，再读目标批次 README，随后检查对应 YAML，最后阅读 `train_experiment.sh` 及其调用的 Python 训练代码。若当前配置格式、数据字段或依赖已经变化，应以解析和训练入口的显式错误为准，不应从脚本名称推断兼容性。
