# 第 4 批：候选预训练 BEST 初始化

## 依据、目标与范围

本批受 `文档/记录/目标草案.md`、AdaLigand 的 `talk/talking/Matcher_单候选闭集配体身份分类新方案.md` 和 `文档/exec_plan/Matcher_单候选闭集身份分类重写执行记录.md` 共同约束。第 4 批将在第 1–3 批全部自然收口后，只依据 validation 结果选择一个候选六分类预训练 `BEST.pt`，再用它初始化完整 Matcher 的候选编码器。

当前只实现可复用的初始化科学契约、错误检查和测试，不决定来源 BEST、任务数量或对照矩阵。本阶段不创建第 4 批 YAML，不同步服务器，不发布 release，不提交或触发 GPU，不读取 calibration 数据或指标。第 3 批冻结 release `Matcher_d15132948a18` 及其受保护接续控制器保持不变。

## 正式初始化契约

- 来源必须是已完成 `candidate_pretrain` 阶段发布的绝对路径 `BEST.pt`；相对路径、`LAST.pt` 和阶段名缩写均拒绝。
- 来源 checkpoint、阶段 `resolved.json`、阶段 `summary.json`、运行 `run.json`、运行根 `summary.json` 与训练 YAML 必须在计划、阶段、epoch、global step、selection score、W&B online run、模型、训练、数据和追踪配置上自洽。
- 来源候选预训练的 YAML 与 `resolved.json.stage.initialize_candidate_from` 都必须显式为 `null`，防止把继承过其它 checkpoint 的来源误称为从零候选预训练。
- 来源与目标必须在聚合方式、三组特征开关、模型宽度、注意力头数、dropout、体素通道和 RAUNet 结构上兼容；完整 Matcher 独有的图网络层数不参与候选编码器结构比较。
- 来源与目标必须具有相同的 `data_root/stage1_root/output_root/coverage_threshold/selection_seed/pp_top_k/local_crop_strategy`。工作进程数、预取量和单工作进程缓存只影响 I/O，不参与来源—目标科学比较。
- 初始化前先核对来源与目标候选编码器的全部参数名、形状和 dtype；全部通过后才严格加载 `model.candidate_encoder`。语言、配体图、清单交互和身份打分分支保持目标模型自己的初始化。
- 初始化发生在 `model.to(device)` 和 optimizer 构造前。失败路径不改变目标候选或非候选参数，不推进 Torch 随机状态，也不进入 calibration。

字段缺失兼容只存在于历史产物恢复入口：三个模型特征开关缺失时迁移为 `false`，`local_crop_strategy` 缺失时迁移为 `fixed_center`，候选阶段 `identity_scope` 缺失时迁移为 `null`。正式 YAML 解析仍要求全部字段显式存在。

## 一次性运维取证边界

用户明确要求发布系统与文件字节取证不进入训练主线。正式 `matcher` 包和目标 `resolved.json` 因此不读取来源 `launch.json`、`run_cmd.sh` 或 release manifest，也不计算或持久化这些文件的 SHA-256。

选定实际来源 BEST 后，提交者必须在启动第 4 批前为该来源建立并复核一次性 `tmp/batch4_source_audit/audit_candidate_pretrain_source.py`：核对来源 checkpoint、训练记录、launch、release manifest 和训练 YAML 的路径关系，记录 manifest 声明的内容摘要及关键文件当时的字节摘要，把严格 JSON 报告写到 `/storage/penghongen/tmp/Matcher/diagnostics/`，并在对应单任务记录与本批记录中保存命令、报告路径和结果。`tmp/` 被 Git 忽略，当前累计学习主线不提供或承诺该临时文件；不能把历史工作区中的同名脚本直接当作未来来源的已验收工具。该一次性脚本不独立重算或证明整棵 release 目录的内容摘要，不被正式包导入，不读取 calibration，也不参与模型、损失、选模或训练运行时。

## 实现与验证状态

- `matcher/training/initialization.py` 定义来源语义核对、候选结构兼容判断和严格参数加载。
- `matcher/training/engine.py` 在设备迁移和 optimizer 构造前调用初始化，并把不含文件摘要的来源语义记录写入 `resolved.json.initialization`。
- `matcher/training/config.py` 只允许完整 Matcher 使用绝对 `BEST.pt`；候选预训练阶段必须从零开始。
- `matcher/tests/test_initialization.py` 使用候选子模块和非候选哨兵，覆盖成功加载、随机状态不变、历史字段迁移、非 BEST、数据/结构错配、未完成运行、训练 YAML 漂移、来源非从零和 state-dict 不兼容。
- `训练与运行/README.md` 逐字段定义 `resolved.json` 和初始化记录，并明确一次性运维取证与正式训练代码的职责分界。
