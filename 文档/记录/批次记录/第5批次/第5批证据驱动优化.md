1. 裁剪方向：A800 成对运行 `clip5` 与 `clip200`。前者仍裁掉一部分中位更新并保留尾部保护；后者只有实际触发率不超过 `0.1%` 时才称近似不裁剪。

3. 学习率方向：当前双门任务前四轮连续改善，ReduceLROnPlateau 也会在坏验证轮后降学习率；没有证据支持同时提交 `2e-4`，本轮不增加学习率任务。
4. 判断仍同时读取 validation selection score、六分类与身份指标；单个指标或单轮波动不构成负优化结论。

## 已实现并用于首项的诊断边界

当前第 5 批候选实现为正式模型配置增加 `initial_graph_gate` 与 `initial_inventory_gate`。二者都是 `[0,1]` 内的有限初值；训练后仍为不受该区间限制的可训练标量。第 0–4 批 22 份正式 YAML 共 23 个阶段均显式写 `0.0`，候选预训练还会拒绝任何非零值，因此既有任务的模型结构与初始数值不变。历史 checkpoint 与 `resolved.json` 缺少字段时只在恢复入口迁移为 `0.0`；正式 YAML 缺字段立即失败。

完整 Matcher 的 validation 正式前向在完成全部输入校验和三个配对打分器计算时，同时保存语言基线、已乘图门增量与已乘清单门增量。诊断在 `model.eval()` 与 `torch.inference_mode()` 下直接读取同批组件，不重跑打分器，也不再次执行由 `torch.any(...)` 触发的 device→host 布尔判定。对每个具有有效身份目标且至少两个有效身份槽的候选，先在有效槽内分别去均值，再计算 L2 范数；这会排除对排序没有作用的候选内常数平移。绝对范数对全部上述候选取均值；相对比例只在语言基线范数大于 `1e-12` 时逐候选计算后取均值。补零身份槽不参与计算，每个物理批次新增的唯一 device→host 传输是一组聚合标量。

W&B 独立使用 `identity_contribution/validation/*`：记录多身份有效候选数、语言基线非零候选数、三条分支的中心化范数均值，以及图、清单和两者合计相对语言基线的均值。无有效分母的比例不发送。该树不进入损失、validation 指标、selection score、`EvaluationResult`、`history.jsonl`、checkpoint 或 calibration 产物；它只为选择第 5 批首个非零门初值提供证据，不能单独判定优化正负。
